# Техническое задание

## Smart Layout Switcher для macOS

**Кодовое имя проекта:** SmartSwitcher
**Версия документа:** 1.0
**Дата:** 8 июня 2026
**Платформа:** macOS 13 Ventura и новее (Apple Silicon + Intel)
**Стек:** Swift 5.9+ / AppKit / SwiftUI (настройки)
**Назначение документа:** полное ТЗ для разработки приложения автоматического переключения раскладки клавиатуры — современного аналога Punto Switcher для macOS. Документ предназначен для использования в качестве рабочего задания при разработке через Claude CLI.

---

## 1. Анализ конкурирующих продуктов

### 1.1 Обзор рынка

Класс программ — «auto layout switcher»: фоновые утилиты, которые отслеживают ввод и автоматически исправляют текст, набранный в неверной раскладке (`ghbdtn` → `привет`). Родоначальник жанра — Punto Switcher (2001, Windows). Нативного встроенного решения в macOS нет: система не умеет распознавать «осмысленность» набранного слова и сама раскладку не меняет.

### 1.2 Таблица конкурентов

| Продукт | Платформы | Цена | Языки | Сильные стороны | Слабые стороны |
|---|---|---|---|---|---|
| **Punto Switcher** (Яндекс) | Windows, частично macOS | Бесплатно | RU/EN | Зрелые словари, автозамена, дневник | На macOS заброшен, глючит, телеметрия Яндекса, нет Apple Silicon-оптимизации |
| **Caramba Switcher** | Windows, macOS | Win — бесплатно; **Mac — платно** (годовая подписка) | Только RU/EN | Автор — создатель Punto, умное определение языка редактируемого текста, минимум ложных срабатываний, self-learning | Платно на Mac, только 2 языка, почти нет настроек, жалобы на блокировку выключения ПК |
| **Lang Switcher** | macOS | Freemium / платно | RU/EN/ES/FR/DE и др. | Много языков, app-specific исключения, горячие клавиши, быстрый | Нет CJK (японский/корейский), сообщения о багах и нестабильности в некоторых версиях |
| **Mahou** | **Только Windows** | Бесплатно, GPL v2 | Мультиязык | Open-source, гибкий | На macOS не работает в принципе |
| **reg2005/langSwitcher** | macOS | Бесплатно, open-source | 5 раскладок | Нативный Swift, Double-Shift, greedy line detection, menu bar | Конвертер по хоткею, не полноценный «авто» в реальном времени |
| **graninilya/keyswitcher** | macOS | Бесплатно, open-source | RU/EN | Нативный, заточен под Apple Silicon, «как Punto» | Ранняя стадия, ограниченный функционал |
| **Keyboard Maestro / Karabiner** | macOS | Платно / бесплатно | — | Мощная автоматизация ввода | Не специализированы под детект языка, требуют ручной настройки |

### 1.3 Выводы и рыночная ниша

Ключевая боль всех решений — **ложные срабатывания** (переключение там, где не надо: имена, команды, пароли, термины). Побеждает тот, у кого лучше «мозг» — детектор языка, а не количество фич. Бесплатные нативные решения на Mac либо сырые, либо являются конвертерами по хоткею, а не настоящими авто-свитчерами.

**Наша ниша:** нативное (Swift, Apple Silicon), бесплатное/freemium, open-core приложение с качественным статистическим детектором языка, расширяемым набором языков (не только RU/EN) и прозрачной приватностью (никакой телеметрии набранного текста). Дифференциация — точность детекта + честная приватность + открытый код ядра.

## 2. Цели и функциональность

### 2.1 Цели продукта

1. Автоматически и незаметно исправлять текст, набранный в неверной раскладке, в реальном времени по завершении слова.
2. Свести ложные срабатывания к минимуму за счёт статистического детектора и системы исключений.
3. Работать нативно и быстро, не вносить ощутимой задержки в ввод (< 5 мс на обработку события клавиши).
4. Гарантировать приватность: набранный текст никогда не покидает устройство.
5. Поддержать минимум RU/EN на старте с архитектурой, готовой к добавлению других языков.

### 2.2 Функциональные требования (FR)

**FR-1. Перехват ввода.** Глобальный перехват нажатий клавиш через `CGEventTap` (на уровне `kCGSessionEventTap`). Буферизация символов текущего «слова» до разделителя (пробел, Enter, Tab, знаки препинания).

**FR-2. Детект языка.** Анализ накопленного слова/строки: определить, является ли набор осмысленным в текущей раскладке или это «мусор», который станет осмысленным в другой. Алгоритм — комбинация:
- словарь невозможных буквосочетаний (например, латинские слова без гласных подряд);
- частотная модель биграмм/триграмм символов для каждого языка;
- словарь частотных слов (быстрая проверка);
- стоп-листы (команды, домены, e-mail, числа, пути).

**FR-3. Автопереключение и перенабор.** При уверенном детекте: сменить активный input source (`TISInputSource` / `TISSelectInputSource`), удалить неверно набранное слово (эмуляция Backspace), вставить корректный текст в новой раскладке. Курсор и выделение сохраняются.

**FR-4. Ручные хоткеи.**
- Double-Shift — исправить раскладку последнего слова/выделения вручную.
- Single-Shift (опционально) — сменить текущую раскладку.
- Настраиваемая «горячая отмена» — откатить последнее авто-исправление (как Backspace-undo в Punto).

**FR-5. Система исключений.**
- Белый список приложений (не работать в Терминале, менеджерах паролей, играх).
- Чёрный/белый список слов (никогда/всегда исправлять конкретные слова).
- Игнор полей ввода паролей (по возможности через accessibility-атрибуты secure text field).

**FR-6. Обучение (self-learning).** Если пользователь откатывает исправление — слово/паттерн заносится в исключения. Локальная адаптивная модель.

**FR-7. Автозамена и расширения текста (опционально, фаза 2).** Пользовательские правила «сокращение → текст».

**FR-8. Звук и уведомления.** Опциональный звуковой сигнал при срабатывании; ненавязчивые уведомления.

**FR-9. Menu bar UI.** Иконка в строке меню: вкл/выкл, текущая раскладка, быстрый доступ к настройкам, пауза.

**FR-10. Настройки.** Окно настроек (SwiftUI): языки, хоткеи, исключения, поведение, звук, автозапуск, обновления, приватность.

**FR-11. Дневник/история (опционально, фаза 2, выкл по умолчанию).** Локальный лог исправлений для отладки; полностью отключаемый, с явным предупреждением о приватности.

### 2.3 Нефункциональные требования (NFR)

- **Производительность:** обработка события клавиши < 5 мс; потребление RAM в покое < 60 МБ; near-zero CPU в простое.
- **Надёжность:** не терять и не дублировать ввод; не блокировать систему; корректно работать при потере прав доступа.
- **Приватность:** ноль сетевой передачи набранного текста; все словари и модель — локально.
- **Совместимость:** macOS 13+, arm64 + x86_64 (universal binary).
- **Доступность:** поддержка VoiceOver в окне настроек.

## 3. Архитектура программы

### 3.1 Принципы

Модульная архитектура с чётким разделением: детектор языка изолирован как заменяемый компонент (это «мозг» и точка роста качества). Перехват ввода отделён от логики принятия решений.

### 3.2 Модули

```
SmartSwitcher.app
├── Core
│   ├── EventTapManager      — CGEventTap, перехват/инъекция клавиш
│   ├── InputBuffer          — буфер текущего слова, границы слов
│   ├── LayoutController     — TISInputSource: чтение/смена раскладки
│   └── TextReplacer         — удаление и перенабор текста
├── Brain (заменяемый модуль детекта)
│   ├── LanguageDetector     — протокол + реализация
│   ├── NGramModel           — частотные биграммы/триграммы
│   ├── DictionaryService    — словари слов, стоп-листы
│   └── HeuristicsEngine     — правила (числа, пути, e-mail, регистр)
├── Rules
│   ├── AppExclusionManager  — белый список приложений
│   ├── WordRulesManager     — исключения по словам
│   └── LearningStore        — адаптивные исключения
├── UI
│   ├── MenuBarController    — NSStatusItem
│   ├── SettingsWindow       — SwiftUI
│   └── Onboarding           — выдача прав Accessibility
├── Services
│   ├── HotkeyManager        — глобальные хоткеи
│   ├── UpdateService        — Sparkle (обновления)
│   ├── LicenseService       — лицензирование/монетизация
│   ├── SyncService          — синхронизация настроек (iCloud/файл)
│   ├── LocalizationService  — i18n
│   └── ImportExportService  — экспорт/импорт данных
└── Infrastructure
    ├── Preferences          — UserDefaults / файл конфигурации
    ├── Logger               — приватный лог (без текста ввода)
    └── PermissionsManager   — Accessibility, проверки прав
```

### 3.3 Поток данных

```
Нажатие клавиши
   → EventTapManager (перехват)
   → InputBuffer (накопление слова)
   → [разделитель?] → нет → пропустить событие дальше
                    → да  → Brain.LanguageDetector.analyze(word)
                          → Rules (исключения, приложение, секретное поле)
                          → [нужно исправить + разрешено?]
                                → да → LayoutController.switch()
                                      → TextReplacer.replace()
                                → нет → ничего
```

### 3.4 Ключевые системные API macOS

- `CGEvent.tapCreate` / `CGEventTapEnable` — перехват клавиатуры (требует Accessibility).
- `TISCopyCurrentKeyboardInputSource`, `TISSelectInputSource`, `TISCreateInputSourceList` — раскладки.
- `CGEvent(keyboardEventSource:virtualKey:keyDown:)` — инъекция нажатий для перенабора.
- `UCKeyTranslate` / `TISGetInputSourceProperty` — маппинг клавиша↔символ для конкретной раскладки.
- `NSWorkspace.shared.frontmostApplication` — определение активного приложения.
- `AXUIElement` (Accessibility API) — определение secure text field (пароли).
- `SMAppService` — автозапуск (login item, macOS 13+).

## 4. Дизайн пользовательского интерфейса

### 4.1 Принципы UI

Минимализм в духе macOS HIG. Приложение должно быть «невидимым» в работе. Основное взаимодействие — через menu bar; настройки открываются по необходимости. Поддержка светлой/тёмной темы автоматически.

### 4.2 Menu bar

Иконка-буква текущей раскладки (RU/EN) или нейтральный значок. Меню:
- Тумблер «Включено / Пауза».
- Текущая раскладка.
- «Настройки…».
- «Приостановить на 10 минут».
- «О программе» / «Проверить обновления».
- «Выход».

### 4.3 Окно настроек (SwiftUI, вкладки)

- **Общие:** автозапуск, язык интерфейса, тема, звук срабатывания.
- **Языки:** список активных языков/раскладок, приоритеты.
- **Хоткеи:** настройка Double-Shift, отмены, ручного переключения.
- **Исключения:** список приложений (с переключателями), список слов, импорт/экспорт.
- **Приватность:** статус обработки данных, тумблер дневника (по умолчанию выкл), кнопка «Очистить локальные данные».
- **Обновления:** канал (стабильный/бета), автопроверка.
- **Аккаунт/Лицензия:** статус, активация, восстановление покупок (фаза монетизации).

### 4.4 Онбординг

Первый запуск: пошаговый мастер выдачи прав Accessibility (со скриншотами), выбор языков, краткий тур по хоткеям.

### 5.2 Подход к разработке (фазы)

- **Фаза 0 — каркас:** menu bar app, выдача прав Accessibility, EventTap «слышит» клавиши (лог в консоль).
- **Фаза 1 — MVP детекта:** буфер слова, простой эвристический детектор RU/EN, смена раскладки и перенабор, Double-Shift.
- **Фаза 2 — умный мозг:** n-gram модель, словари, стоп-листы, система исключений, обучение.
- **Фаза 3 — продукт:** настройки SwiftUI, локализация, обновления (Sparkle), синхронизация, импорт/экспорт.
- **Фаза 4 — монетизация и релиз:** лицензирование, сайт, нотаризация, дистрибуция.

### 5.3 Критерии «работает»

Каждая фаза закрывается, когда: код собирается без warning'ов, проходят unit-тесты профильных модулей, ручной smoke-тест по чек-листу пройден.

## 7. Тестирование и отладка

### 7.1 Виды тестов
- **Unit:** детектор языка (корпус «правильно/мусор»), маппинг раскладок, буфер слов, правила исключений.
- **Integration:** связка EventTap → детект → перенабор на тестовых сценариях.
- **Регрессионные:** золотой набор фраз с ожидаемым результатом исправления.
- **Ручные сценарии:** разные приложения (браузер, заметки, мессенджеры, IDE, терминал), быстрый ввод, copy-paste, эмодзи.

### 7.2 Метрики качества детекта
- **Precision** (доля верных исправлений среди сделанных) — целевая > 98%.
- **Recall** (доля пойманных «мусорных» слов) — целевая > 90%.
- Отдельный фокус на минимизацию ложных срабатываний (false positives важнее recall).

### 7.3 Отладка
- Режим диагностики с логом решений детектора (без сохранения самого текста по умолчанию).
- Сбор анонимной статистики срабатываний только с явного согласия.

## 8. Оптимизация и производительность

- Обработчик EventTap — максимально лёгкий; тяжёлый анализ выносить из горячего пути, выполнять только на границе слова.
- N-gram модели загружать лениво и держать в компактных бинарных структурах (не парсить текст в рантайме).
- Профилирование через Instruments (Time Profiler, Allocations) на каждой фазе.
- Бенчмарк: латентность обработки клавиши, время детекта слова, пиковая память.
- Universal binary, оптимизация под Apple Silicon.

## 10. Совместимость с ОС и устройствами

- **Целевая ОС:** macOS 13 Ventura и новее (приоритет — текущая и предыдущая мажорные версии).
- **Архитектуры:** Apple Silicon (arm64) и Intel (x86_64) — universal binary.
- **Раскладки:** стандартные системные input sources; поддержка кастомных раскладок через `UCKeyTranslate`.
- **Будущее (вне MVP):** возможный порт логики ядра на другие ОС не предусмотрен — приложение нативно «маковское»; кроссплатформенность ограничивается перепроектированием, а не текущим ТЗ. Внутри платформы — тестирование на разных моделях Mac и версиях ОС.

## 11. Защита и безопасность данных

- **Принцип privacy-by-design:** набранный текст обрабатывается строго в памяти, не пишется на диск и не отправляется в сеть.
- Дневник/история — выключены по умолчанию, шифруются при включении, легко очищаются.
- Игнорирование полей ввода паролей (secure text fields) через Accessibility-атрибуты.
- Песочница App Store по возможности; если EventTap требует выхода из sandbox — распространение вне App Store с нотаризацией и hardened runtime.
- Хранение лицензионных данных — в Keychain.
- Подпись кода (Developer ID), нотаризация Apple, hardened runtime.

---

## 12. Обработка исключений и ошибок

- Защита от потери прав Accessibility: детект отключения, уведомление пользователю, безопасный простой без падений.
- Graceful degradation: если раскладка/символ не маппится — не трогать ввод.
- Обработка edge-cases: очень быстрый ввод, программная вставка текста, multi-byte символы, dead keys, IME (CJK) — для неподдерживаемых случаев модуль молчит, а не ломает ввод.
- Глобальный перехват исключений с записью в приватный лог.

## Приложение A. Технические риски

1. **Sandbox vs EventTap.** Глобальный перехват клавиш конфликтует с App Store sandbox. Вероятный путь — распространение вне App Store (Developer ID + нотаризация). Решить на фазе 0.
2. **Точность детекта** — главный риск качества; смягчается корпусом тестов и приоритетом precision над recall.
3. **Хрупкость перенабора** в приложениях с нестандартной обработкой ввода (Electron, IDE, игры) — смягчается белым списком приложений.
4. **Изменения приватности/прав в новых macOS** — мониторинг бета-версий ОС.

- Линт: SwiftLint. Тесты: XCTest. Док: DocC. CI: GitHub Actions.
- Сборка: Xcode 15+, universal binary, hardened runtime, нотаризация.
