# ADR-0008: Надёжный режим — активный tap с придерживанием ввода

Дата: 2026-10-28. Статус: принято, режим включён по умолчанию (решение
владельца продукта 2026-10-28). Заменяет ADR-0001 как режим по умолчанию,
дополняет ADR-0005.

## Контекст
Listen-only tap (ADR-0001) исправляет слово пост-фактум: Backspace×N и
вставка. Интеграционный тест показал гонку: при очень быстром наборе
следующая буква попадает в середину перенабора (`ghbdtn d` → `gприветв`).
Кроме того, слово перед Enter не исправляется вовсе (ADR-0005).

## Решение
«Надёжный режим» (включён по умолчанию) использует активный
`CGEventTap`:
- на время перенабора `InputGate` забирает нажатия пользователя (keyDown и
  keyUp) и воспроизводит их в исходном порядке сразу после замены; движок
  получает keyDown сразу, поэтому порядок в его очереди не меняется;
- Enter без Cmd/Ctrl/Option: если слово перед курсором нужно исправить,
  Enter поглощается, слово исправляется, Enter повторяется;
- предохранитель: удержание не дольше 0,5 с, даже если движок завис.

В listen-only режиме окно гонки сокращено ускорением перенабора
(0,5 мс между событиями).

## Последствия
- (+) Быстрый набор не смешивается с перенабором; слово перед Enter тоже
  исправляется.
- (−) Приложение в пути событий: при сбое ввод может задержаться до 0,5 с.
  Это осознанное отступление от NFR ТЗ «не задерживать ввод»: гонка с
  быстрым набором портит текст, а задержка ограничена предохранителем.
  Выключение режима в настройках возвращает чистый listen-only.
